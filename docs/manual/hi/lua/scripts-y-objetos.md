# स्क्रिप्ट किसी ऑब्जेक्ट का एक कंपोनेंट है

Whisk3D में कोई स्क्रिप्ट हमेशा सीन के किसी **ऑब्जेक्ट** की होती है (एक मेश, एक एम्प्टी, एक 2D बटन…)। एक ऑब्जेक्ट में कई स्क्रिप्ट हो सकती हैं; हर स्क्रिप्ट अपने वेरिएबल के साथ अलग से चलती है, उसी क्रम में जिसमें वे दिखती हैं।

स्क्रिप्ट के अंदर, `yo()` उस ऑब्जेक्ट को लौटाता है जिसकी यह स्क्रिप्ट है। *दूसरे* ऑब्जेक्ट इस्तेमाल करने के लिए, स्क्रिप्ट `propiedades` नाम की एक ग्लोबल टेबल घोषित करती है। एडिटर उसे पढ़ता है और Properties पैनल में, स्क्रिप्ट के कार्ड में हर एंट्री के लिए एक फ़ील्ड दिखाता है:

```lua
propiedades = {
  pelota     = "objeto",                          -- सीन का कोई ऑब्जेक्ट चुनने के लिए एक फ़ील्ड
  dificultad = { "facil", "normal", "dificil" },  -- एक ड्रॉपडाउन सूची (पहला विकल्प डिफ़ॉल्ट है)
  velocidad  = 200,                               -- स्क्रिप्ट इस्तेमाल करने वाले हर ऑब्जेक्ट की अपनी एक संख्या
  activo     = true,                              -- एक हाँ/नहीं
  etiqueta   = "caja",                            -- एक टेक्स्ट
}

function inicio()
  local p   = objeto("pelota")         -- "pelota" फ़ील्ड में चुना गया ऑब्जेक्ट
  local dif = opcion("dificultad")     -- "facil", "normal" या "dificil"
  local v   = propiedad("velocidad")   -- 200, या उस ऑब्जेक्ट में जो भी डाला गया हो
end
```

इस तरह, एक ही स्क्रिप्ट अलग-अलग वैल्यू वाले कई ऑब्जेक्ट के काम आती है: एक दुश्मन का `velocidad` फ़ील्ड 200 हो सकता है और दूसरे का 350।

> [!NOTE]
> `propiedades` पढ़ने के लिए एडिटर **फ़ाइल को चलाता है**, भले ही गेम न चल रहा हो। इसलिए फ़ंक्शन के बाहर सिर्फ़ घोषणाएँ रखें (टेबल, कॉन्स्टेंट, `local`), कभी भी ऐसा कोड नहीं जो कुछ करता हो।

स्क्रिप्ट आपस में वेरिएबल शेयर नहीं करतीं। एक-दूसरे को डेटा देने के लिए (पॉइंट, खिलाड़ी जीता या नहीं…) वे एक साझा जगह का इस्तेमाल करती हैं: `setCompartido("puntos", 10)` लिखता है और `compartido("puntos")` पढ़ता है। इसमें संख्याएँ, हाँ/नहीं और टेक्स्ट रखे जा सकते हैं, और गेम रोकने पर यह ख़ाली हो जाती है।
