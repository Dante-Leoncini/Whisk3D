1. Qué es Lua y para qué se usa en Whisk3D

Lua es un lenguaje de programación chico, rápido y fácil de aprender. Whisk3D trae adentro Lua 5.4 y lo usa para la lógica de los juegos: mover un personaje con las teclas, contar puntos, abrir un menú, reproducir un sonido cuando algo choca.

Los scripts se escriben en el editor de scripts de Whisk3D (o en cualquier editor de texto) y se guardan como archivos .lua, normalmente dentro del proyecto .w3d (en su carpeta scripts/). Solo corren cuando el juego está en marcha: con el timeline en modo Juego y Play, o en un juego compilado.

Comentarios

Variables y tipos

Una variable se crea al asignarle un valor. Usá siempre local: la variable existe solo dentro del bloque donde se declaró y no choca con otras.

local vidas = 3           -- número (entero)
local velocidad = 2.5     -- número (con decimales)
local nombre = "Whisky"   -- texto (string)
local vivo = true         -- booleano: true o false
local nada = nil          -- nil = "sin valor"

Los tipos de Lua son: nil, boolean, number, string, table y function. Los objetos de la escena que te da Whisk3D son un tipo especial que solo se usa pasándolo a las funciones del motor.

En Lua, solo false y nil son "falso". El 0 y el texto vacío "" cuentan como verdadero.

Decisiones: if

if vidas <= 0 then
  print("perdiste")
elseif vidas == 1 then
  print("última vida")
else
  print("seguís jugando")
end

Repeticiones: for y while

for i = 1, 10 do          -- de 1 a 10
  print(i)
end
for i = 10, 0, -2 do      -- de 10 a 0, de a 2 para abajo
  print(i)
end
local n = 0
while n < 5 do
  n = n + 1
end

Lua no tiene n++ ni n += 1: se escribe n = n + 1. Para cortar un bucle se usa break.

Funciones

local function sumar(a, b)
  return a + b
end
print(sumar(2, 3))        -- 5

-- una función puede devolver varios valores
local function minMax(a, b)
  if a < b then return a, b else return b, a end
end
local menor, mayor = minMax(8, 3)

Muchas funciones de Whisk3D devuelven varios valores a la vez, por ejemplo local x, y, z = posicion(yo()).

Tablas: listas y diccionarios

La tabla es la única estructura de datos de Lua y sirve para todo.

-- como lista (los índices empiezan en 1, no en 0)
local frutas = { "manzana", "pera", "uva" }
print(frutas[1])          -- manzana
print(#frutas)            -- 3
frutas[#frutas + 1] = "kiwi"   -- agregar al final
table.insert(frutas, "melón")  -- otra forma

for i, f in ipairs(frutas) do  -- recorrer una lista en orden
  print(i, f)
end

-- como diccionario (clave = valor)
local jugador = { nombre = "Ana", puntos = 0 }
jugador.puntos = jugador.puntos + 10
print(jugador["nombre"])  -- Ana

for clave, valor in pairs(jugador) do  -- recorrer todas las claves (sin orden fijo)
  print(clave, valor)
end

Textos y números útiles

local t = string.format("Puntos: %d  Tiempo: %.1f", 120, 3.456)  -- "Puntos: 120  Tiempo: 3.5"
local may = string.upper("hola")        -- "HOLA"
local parte = string.sub("Whisk3D", 1, 5)   -- "Whisk"
local n = tonumber("42")                -- texto a número

local d = math.sqrt(16)                 -- 4.0
local a = math.abs(-3)                  -- 3
local m = math.max(4, 9, 2)             -- 9

Para números al azar, Whisk3D tiene azar() (ver la referencia). También anda math.random, que ya viene sembrado distinto en cada partida.

3. Un script es un componente de un objeto

En Whisk3D un script siempre pertenece a un objeto de la escena (una malla, un vacío, un botón 2D…). Un objeto puede tener varios scripts; cada uno corre por separado, con sus propias variables, en el orden en que aparecen.

Desde el script, yo() devuelve el objeto dueño. Para usar otros objetos, el script declara una tabla global llamada propiedades. El editor la lee y muestra un campo por cada entrada en la tarjeta del script, en el panel de Propiedades:

propiedades = {
  pelota     = "objeto",                          -- un campo para elegir un objeto de la escena
  dificultad = { "facil", "normal", "dificil" },  -- una lista desplegable (la primera es la de fábrica)
  velocidad  = 200,                               -- un número propio de cada objeto que use el script
  activo     = true,                              -- un sí/no
  etiqueta   = "caja",                            -- un texto
}

function inicio()
  local p   = objeto("pelota")         -- el objeto elegido en el campo "pelota"
  local dif = opcion("dificultad")     -- "facil", "normal" o "dificil"
  local v   = propiedad("velocidad")   -- 200, o lo que se haya puesto en ese objeto
end

Así, el mismo script sirve para muchos objetos con valores distintos: el campo velocidad de un enemigo puede valer 200 y el de otro 350.

Para leer propiedades, el editor ejecuta el archivo aunque el juego no esté corriendo. Por eso, afuera de las funciones poné solo declaraciones (tablas, constantes, local), nunca código que haga cosas.

Los scripts no comparten variables entre sí. Para pasarse datos (los puntos, si el jugador ganó…) usan un espacio compartido: setCompartido("puntos", 10) escribe y compartido("puntos") lee. Guarda números, sí/no y textos, y se vacía al detener el juego.

4. Cuándo llama el motor a tu script

Tu script define funciones con nombres especiales y el motor las llama solo, en el momento justo. Todas son opcionales: escribí solo las que necesites.

FunciónCuándo se llama
inicio()Una vez, al darle Play (o apenas se crea el objeto con instanciar). Sirve para buscar objetos y preparar variables.
actualizar(dt)En cada cuadro, mientras el objeto esté visible y en la escena activa. dt son los segundos que pasaron desde el cuadro anterior (entre 0.001 y 0.1).
alEntrar(otro, miHitbox, suHitbox)Cuando un hitbox empieza a tocar a otro.
alQuedarse(otro, miHitbox, suHitbox)En cada cuadro mientras siguen tocándose.
alSalir(otro, miHitbox, suHitbox)Cuando dejan de tocarse (también si uno se oculta o se desactiva).
alTocar(otro, impulso, x, y, z, nx, ny, nz)Cuando dos cuerpos rígidos chocan. x, y, z es el punto de contacto y nx, ny, nz la dirección hacia el otro.

Los eventos de hitbox los reciben los scripts del hitbox y los de su objeto padre. Si el otro es un cuerpo rígido, suHitbox llega como nil.

Mover cosas con dt

Multiplicá siempre las velocidades por dt. Así el juego va igual de rápido en una PC potente y en un teléfono lento:

function actualizar(dt)
  mover(yo(), 3 * dt, 0, 0)   -- 3 unidades por segundo hacia +X
end

Orden dentro de un cuadro

  1. Física (velocidades, cuerpos rígidos) y los eventos de choque: alTocar, alSalir, alEntrar, alQuedarse.
  2. actualizar(dt) de todos los scripts, en el orden del outliner.
  3. Animaciones (escena, clips, esqueletos).
  4. Fin del cuadro: se aplican los destruir() pendientes, entran los objetos instanciados y se hace el cambiarEscena() pedido.

Al detener el juego

Al apretar Stop se cierran todos los scripts, se borra lo compartido y la escena vuelve a como estaba antes del Play. Si editás un script mientras el juego corre, ese objeto lo recarga: sus variables vuelven a cero y se llama otra vez a inicio(). Rebobinar el timeline devuelve los objetos a su lugar, pero no las variables de Lua.

5. Ejes, unidades y objetos

  • 3D: en los scripts el eje Y apunta para arriba. El panel de Propiedades muestra Z arriba, así que el campo "Z" del panel es la y del script. Las posiciones, rotaciones y escalas son relativas al padre del objeto. Las rotaciones van en grados.
  • 2D (pantalla y UI): píxeles del lienzo, con el (0, 0) en el centro; +x hacia la derecha y +y hacia abajo.
  • Objetos: las funciones que buscan o devuelven objetos (yo, buscar, objeto…) dan un valor que no tiene campos ni métodos: se lo pasás a otras funciones. Dos objetos se pueden comparar con ==. Si el objeto se destruyó, se comporta como nil.
  • Tolerancia: casi todas las funciones aceptan nil o un objeto del tipo equivocado sin romper nada: las que leen devuelven 0, "" o false y las que escriben no hacen nada.
  • Índices: como en Lua, casi todo empieza en 1 (vértices, dedos, capas, pasos de rutina). La excepción son las memorias de las rutinas (memoria), que van de 0 a 255.

Rutinas y memorias

Las rutinas (listas de pasos de dibujo que se arman en el panel de Propiedades) pueden leer valores que pone Lua. Cada memoria es un bloque de 256 números con nombre, y los pasos la leen como @nombre[i].

FunciónQué hace
setMemoria(nombre, i, v), memoria(nombre, i), setMemorias(nombre, i, v1, v2, ...)Escribir y leer memorias (el índice va de 0 a 255).
setPaso(rutina, i, campo, ...), leerPaso(rutina, i, campo)Cambiar o leer un paso de una rutina (campos: "on", "n", "color", "ref", "modo", "entero").
paso(nombre, ...)Ejecuta un paso de dibujo; solo vale dentro de una función llamada por el paso "Llamar Lua" de una rutina.

En una rutina con Repetir mayor que 1, la memoria bucle dice en qué vuelta va: @bucle[0] es la vuelta actual (desde 0) y @bucle[1] el total.

8. Ejemplos completos

Hola mundo: mover un cuadro 2D con las flechas

propiedades = { cuadro = "objeto" }

function inicio()
  beep(440, 120, 0.5)          -- un pitido para saber que arrancó
end

function actualizar(dt)
  local c = objeto("cuadro")
  local x, y = posPx(c)
  if tecla("arriba") then y = y - 200 * dt end
  if tecla("abajo")  then y = y + 200 * dt end
  setPosPx(c, x, y)
end

Un personaje 3D que camina y salta

propiedades = { velocidad = 4, salto = 6 }

local vy = 0                   -- velocidad vertical (para el salto)

function actualizar(dt)
  local yo_ = yo()
  local v = propiedad("velocidad")
  local dx, dz = 0, 0
  if tecla("izquierda") then dx = dx - 1 end
  if tecla("derecha")   then dx = dx + 1 end
  if tecla("arriba")    then dz = dz - 1 end
  if tecla("abajo")     then dz = dz + 1 end
  mover(yo_, dx * v * dt, 0, dz * v * dt)

  -- salto simple: sube, la gravedad lo baja y no pasa del piso (y = 0)
  local x, y, z = posicion(yo_)
  if teclaApretada("espacio") and y <= 0 then vy = propiedad("salto") end
  vy = vy - 9.8 * dt
  y = y + vy * dt
  if y < 0 then y = 0; vy = 0 end
  setPosicion(yo_, x, y, z)
end

9. Límites y consejos

Qué partes de Lua no están

  • Están string, table y math, más las funciones básicas (print, pairs, ipairs, type, tostring, tonumber, pcall, assert…).
  • No están io ni os (un juego no toca archivos del disco; por eso no hay os.time), ni require, coroutine, utf8 ni debug. Para guardar datos usá config / guardarConfig.
  • Cada script es independiente: no puede ver las variables de otro. Para comunicarse, setCompartido / compartido.

Errores

  • Si una función tiene un error, se anota en el registro (archivo.lua:LÍNEA: mensaje) y esa llamada se corta, pero se vuelve a llamar en el cuadro siguiente: el mismo error se repite en cada cuadro hasta que lo arregles.
  • Si el archivo no se puede leer o tiene un error de sintaxis, ese script queda apagado hasta el próximo Play.
  • error("...") en Whisk3D solo anota el mensaje y el script sigue. Si querés cortar, usá assert(condicion, "mensaje").

Cosas a tener en cuenta

  • actualizar solo corre en objetos visibles de la escena activa: ocultar un objeto apaga su lógica.
  • destruir, cambiarEscena y reproducirEscena se aplican al final del cuadro, no en el momento.
  • La fuente de los textos del juego no dibuja tildes ni eñes: escribí "MENU" en vez de "MENÚ".
  • areaSegura, cajaUI y resolucion recién tienen valores reales después del primer cuadro dibujado: no las uses en inicio.
  • En Web y Android solo la primera luz ilumina.
  • En el Nokia N95 no hay mando ni mouse: usá tecla con los nombres del teclado del teléfono. Los números enteros son de 32 bits.

Para que ande rápido (sobre todo en el teléfono)

  • Buscá los objetos una sola vez, en inicio, y guardalos en variables local.
  • Usá las versiones "de a muchos" (setVertices, setVerticesColor) en vez de llamar mil veces a la de uno.
  • Preferí las funciones del motor (desplazarUV, lineaPunto, setRotacion con orden) antes que hacer las cuentas en Lua.
  • Medí con perfilLua y relojMs antes de optimizar a ciegas.
